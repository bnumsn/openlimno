## What's in scope (1.0 + interop charter)

End-to-end pipeline through `case.yaml`:

```
fetch (DEM/Q/climate/watershed/LULC/soil/species — 9 fetchers)
  → preprocess (cross-section/ADCP/QRev/HEC-RAS/River2D legacy imports)
  → hydrodynamics (builtin-1D OR SCHISM via OCI container OR HEC-RAS/TELEMAC/MIKE
    result import)
  → habitat (HSI/WUA cell+HMU+reach;
    drifting-egg Lagrangian;
    composite-overlay; quality grading A/B/C)
  → passage (η = η_A × η_P;
    swim model + Monte-Carlo)
  → regulatory_export (CN-SL712 / US-FERC §4(e) / EU-WFD)
  → provenance (SHA-256 chain;
    `openlimno reproduce` reverifies)
```

All modules implemented and gated. The 1.0 charter scope is closed in
the code; what's missing is **evidence** (D5/D6/D7) — see ADR-0011.

## What's out of scope (explicitly)

Per [`SPEC.md §0.3`](../SPEC.md) and [`CAPABILITY_BOUNDARY_1_0.md §B`](governance/CAPABILITY_BOUNDARY_1_0.md):

- OpenLimno-native 2D/3D hydrodynamic solver
- GPU acceleration
- ML / neural-operator surrogates
- Individual-based / agent-based models in-core (CSV bridges are fine)
- Water temperature / quality / sediment solvers (read results only)
- Web GUI / cloud / multi-tenant / REST API
- Multi-solver BMI interchange
- Multi-language top-level architecture
